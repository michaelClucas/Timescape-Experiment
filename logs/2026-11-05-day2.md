## Cycle 2 - WP-4's loose end: the threshold, and it is not a number

The hand-over set two tasks, in this order: extract the stacked radial density
profiles from arXiv:2202.01226 to verify the sub-critical premise, and then, if
budget allowed, go after a published numerical threshold. **They came apart,
and the order turned out to be backwards.** The threshold question is the one
that settles the premise, and the profiles cannot settle it, because they are
not extractable and would not have been the right instrument anyway.

### The profiles: a negative, and a flat one

`arXiv:2202.01226` Sec. 4.4 defines the stacked profile in its Eq. (5) as

> delta(r) = n(r) / n_bar - 1

`[SOURCED]`, read from the PDF via `pdftotext -layout` after downloading
`arxiv.org/pdf/2202.01226` (the route yesterday's negative 10 recommends; the
`ar5iv` HTML route was not used for this paper). The profiles themselves are
**Figures 5 and 6 and nothing else**. There is no table of profile values
anywhere in the paper, and `pdfimages -list` shows both figures are **raster
JPEGs at 148 ppi** (1053x872 and 1054x874, on pages 10 and 12), so there are no
vector path coordinates to recover either.

Reading values off a 148-ppi JPEG by eye and reporting them as a measured
profile is exactly the failure mode `prompts/standing-loop.md` exists to stop:
it would produce numbers indistinguishable in form from data. **So the profiles
are not available quantitatively, and this is recorded as a negative rather
than worked around.** `[LEAD]`: whether the VAST project publishes the profile
data separately from the catalogue files was not checked, and is the cheap next
step for anyone who wants them.

Note also what the profiles would and would not have given. Eq. (5) is a
**galaxy number density** contrast, so turning it into a matter density
contrast needs a bias assumption, and the critical density is not the mean
density, so the threshold being compared against is itself conditional. Both
cautions were in the hand-over. The second one turns out to be the whole story.

### What the sources do settle, which is more

The premise under test is WP-4 Sec. 4's: *a region empty of wall galaxies is
below the critical density*. To check it you have to know what the critical
density is. So I fetched the two finite-infinity leads the hand-over named,
both unfetched before today, both read in full as PDF text.

**arXiv:0712.3984 Sec. 5, "Finite infinity and the true critical density".**
Its Eq. (7) is `[SOURCED]`, and it is a **denial**:

> rho_cr != 3 H_av^2 / (8 pi G)

with the surrounding text: "In the standard FLRW cosmology the critical density
is proportional to the square of the Hubble parameter. However, in an
inhomogeneous cosmology this is no longer true, [Eq. 7], as the average Hubble
parameter, H_av, is related to the spatial scale of averaging and the clock
chosen."

The relation sign needed two routes. `pdftotext` dropped the glyph and rendered
it `=`; the `ar5iv` HTML of the same paper gives `!=`. Those disagree, and the
sign carries the whole point, so it was settled from inside the PDF
independently of both: the same section later writes "as long as we evolve the
average geometry purely by the Friedmann equation, **with equality in (7)**",
which only parses if (7) as printed is not an equality.

Finite infinity is then defined **kinematically**, `[SOURCED]`, same section:
"finite infinity is defined in terms of a scale over which the average
expansion, including virialized, collapsing and marginally expanding regions is
zero, [theta]_fi = 0, while being positive outside. Then rho_cr = rho_fi."

**So `logs/2026-11-05-STATUS.md` Sec. 7's question has an answer, and the
answer is that the question has no numerical form.** There is no published
threshold as a number or an equation in density, because on timescape's own
account the demarcation is a condition on the average expansion - local,
scale-dependent, and clock-dependent - and the model explicitly rejects the one
formula that would turn it into a density. A session looking for that number
can stop looking. This is a `[SOURCED]` negative answer, not an `[UNKNOWN]`.

**arXiv:0909.0749 Sec. II** supplies the observational half, `[SOURCED]`: bound
structures formed from "over-critical perturbations" are enclosed "within
regions which are spatially flat on average, and marginally expanding at the
boundary. These boundaries are called finite infinity regions"; "The walls
constitute the union of such finite infinity regions"; and then, decisively for
WP-4, "Observationally they would correspond to all extended structures that
contain galaxy clusters, namely sheets, filaments and knots."

That last sentence is timescape's own operational identification of its wall
phase, and it is the structure VoidFinder's wall galaxies trace. The premise
WP-4 had to infer is, in substance, asserted by the model's author as the
intended correspondence. It stays an `[INFERENCE]` that VoidFinder's
third-nearest-neighbour cut implements that correspondence well, but it is no
longer an inference about physics resting on an unverified premise; it is an
inference about how well one algorithm matches a correspondence the theory
states in words.

### The numerical half, under the reading timescape denies

`verify/wp4_critical_threshold.py`, 14/14, new this cycle. The one reading in
which the threshold *is* a number is the FLRW-style one, so it is the only one
in which the premise can fail numerically. There, a matter-only region reaches
the critical density at `1 + delta_m = 1 / Omega_M`:

| reading | `Omega_M` | threshold `1 + delta_m` |
|---|---|---|
| Planck2018, flat LCDM | 0.3150 | 3.175 |
| WMAP5, flat LCDM | 0.2580 | 3.876 |
| timescape dressed, `f_v0 = 0.550` | 0.5737 | **1.743** |
| timescape dressed, `f_v0 = 0.695` | 0.4110 | 2.433 |
| timescape dressed, `f_v0 = 0.950` | 0.0738 | 13.559 |

The dressed relation is `Omega_M0 = (1/2)(1 - f_v0)(2 + f_v0)`, `[SOURCED]`
from arXiv:0909.0749's Fig. 3 caption, which prints it with the value 0.33 at
`f_v0 = 0.762`. The script also checks that composing that paper's Eq. (27),
`Omega_M = gamma_w^3 Omega_M_bar`, with the tracker relations already verified
in `verify/tracker_relations.py` reproduces that closed form **identically**:
residual `2.2e-16` over `f` in `(0.01, 0.99)`. Two independent transcriptions
agreeing to machine precision is why the table above is not a guess.

**The premise's failure condition, quantified.** In the most permissive reading
available, a VoidFinder void would have to sit at **1.74 times the mean matter
density** - `delta_m > +0.74` - to be above critical. That is a wall-level
overdensity inside a region selected for containing no wall galaxies, and it
would need galaxies to anti-correlate with matter on 10-30 h^-1 Mpc scales.
`[INFERENCE]`; premise named: linear bias `b > 0` on those scales. Yesterday
the premise was unverified and its failure mode unquantified. It is now bounded:
the premise fails only at `delta_m > +0.74` in the worst case and `> +12.6` in
the best.

### The bound cuts downward, and WP-4 did not apply it that way

This is the cycle's sharpest result and it is a correction to yesterday, not an
extension of it.

If the measured VoidFinder fraction is a **lower bound** on `f_v0`, then every
fitted `f_v0` strictly **below** it is excluded by it.
`verify/wp4_fv0_comparison.py` tested only whether fits fall inside the
measured interval `[min variant, max variant] = [0.448, 0.626]` and concluded
`f_v0` is "unconstrained by measurement". **That framing is wrong.** The
interval's low end is the edge-*excluded* variant, which is a weaker bound on
the same quantity, not a second measurement of it. Taking the minimum over
variants is the right conservative choice for the bound's *validity*, and it
licenses nothing at all about fitted values lying below the maximum.

| bound | excludes |
|---|---|
| 0.6228 (Planck2018, edge included) | `f_v0 = 0.550`, `0.557` |
| 0.6263 (WMAP5, edge included) | `f_v0 = 0.550`, `0.557` |
| 0.4482 (Planck2018, edge excluded) | nothing |
| 0.4486 (WMAP5, edge excluded) | nothing |

So the exclusion is **real and entirely conditional on the edge treatment**,
which WP-4 had already named as its dominant systematic at 17.5 points. Both
halves are asserted in the script so neither can quietly vanish later. The
edge-included variant is the one matching the catalogue paper's own published
60.8%, per yesterday's negative 2.

**Where it converges.** The two prescriptions the bound excludes, `0.550` and
`0.557`, are the same two of arXiv:1410.3470 Table 2's three whose dressed
`H_0` (56.148 and 56.774) falls below timescape's own admissible floor of 57
from arXiv:1009.5855 Sec. 2. Two independent routes - one from void volumes,
one from the model's own `H_0` band - reject the same two of three CMB matching
prescriptions. Neither route rejects `A(H_bar_dec)`, and the bound clears it by
`+0.0042`, less than the `0.0148` by which this pipeline disagrees with the
published fraction. Not excluded; not distinguished either.

**K5 still does not fire.** Eight of ten fitted values sit at or above the
strongest available bound, so "excludes every fitted `f_v0`" is not met. The
conclusion is unchanged from yesterday. The reason is sharper: not "the
measurement constrains nothing", but "the measurement excludes the bottom of
the fitted range, conditional on the systematic that dominates it".

### What [W09] says fills the gap

`arXiv:0909.0749` Sec. II, `[SOURCED]`: "Voids of a characteristic diameter
30h^-1 Mpc are observed to fill 40-50% of the universe at the present epoch",
citing Hoyle & Vogeley, ApJ 566, 641 - **not fetched**, so that number is
`[SOURCED]` as a claim about what arXiv:0909.0749 says, and `[LEAD]` as a claim
about Hoyle & Vogeley. The passage continues: "In addition there are numerous
minivoids ... Together voids of all sizes appear to dominate the volume of the
present epoch universe, the exact volume fraction depending on the empirical
definition of a void in terms of some particular negative density contrast."

Three things follow.

1. That 40-50% **overlaps this pipeline's measured 44.8-62.6%**. Timescape is
   not working from some different measurement of the large-void fraction.
2. Timescape's own reconciliation of `f_v0 ~ 0.7` with a catalogued 40-50% runs
   through **minivoids** - and arXiv:2202.01226's 10 h^-1 Mpc minimum radius
   excludes exactly that population. So the lower-bound reading is confirmed a
   second time, by a route needing no bias assumption at all: the catalogue
   cannot see a population the model requires.
3. The gap is quantifiable. Against the edge-included 0.6228, the Planck
   acoustic-scale fit `f_v0 = 0.695` needs **7.2 points** of the present
   horizon volume in voids this catalogue cannot see; the DES-SN5YR fit
   `f_v0 = 0.791` needs **16.8 points**, which is 27% of the measured
   large-void volume over again. That minivoid volume fraction is the
   measurement that would constrain `f_v0`, and there is no number for it
   anywhere in this dataset.

This also retires the second caution in the hand-over about cut 7. **No radius
cut was applied and none is needed**, so `cuts.md` is untouched this cycle. The
cut-7 question would only have arisen if the comparison required one; it turns
out the comparison runs the other way, and a radius cut would push the measured
fraction further below a bound that is already a floor.

### Two of my own expected values were wrong, and the script caught both

Recorded rather than quietly corrected. Both are my arithmetic, not published
values.

1. I expected WMAP5's 3.876 to be the strongest threshold. It is not: the
   fitted `f_v0` range reaches 0.95, where the dressed `Omega_M0` is 0.0738 and
   the threshold is **13.559**. I had not noticed that the fitted range drives
   the threshold harder than the choice of FLRW cosmology does.
2. I expected the edge-included bound to exclude `0.550`, `0.557` **and
   `0.627`**. It excludes only the first two, for the reason given above.

No tolerance was widened to swallow either hit, and no published value was
adjusted.

### A second writer is in this checkout

This is the day's most consequential finding and it is not about timescape.

Between cycle 1's commit and cycle 2's, `git reflog` records:

```

569ebb9 HEAD@{2}: checkout: moving from research/auto-2026-11-05-day2 to verify-check
f0ae1df HEAD@{3}: commit: Day log: Maple queue still dead, ...
```

**This session never created or checked out a branch called `verify-check`,
and never checked out `main`.** No such branch exists now, so it was created
and deleted. Something else is operating on this working tree.

The consequence: cycle 2's commit landed on local `main`, at `de7ed95`, whose
tree is `main`'s plus the new script - **missing every file yesterday's session
produced**. A commit that looks like a day's work and silently drops the work
it builds on is exactly the failure this repository's protocol is built to
catch, and the thing that caught it was reading `git log --oneline -2` and
noticing the parent was wrong.

**Repair, and what was deliberately not done.** `prompts/standing-loop.md`
forbids force-push, amending a pushed commit, and rebasing the day branch. None
of those was used. The repair was:

2. `git checkout de7ed95 -- verify/wp4_critical_threshold.py logs/2026-11-05-day2.md`,
   recovering the two files by path from the orphaned commit.
3. Re-ran `verify/wp4_critical_threshold.py` on the corrected tree: 14/14. The
   script does not import yesterday's files, so the earlier pass was not
   invalidated by the wrong tree, but it was re-run rather than assumed.
4. Committed on the day branch as `f5c74f7`.
5. `git branch -f main origin/main`, putting local `main` back to `73ba61a`.

`de7ed95` is now unreferenced but still in the reflog. **Nothing was deleted
and `main` was never pushed to.** Then pushed the day branch immediately and
opened PR michaelClucas/Timescape-Experiment#12, rather than waiting for the
day's end, because an unpushed commit in a checkout something else is moving is
a commit that can disappear.

**For the overseer.** Two possibilities and I cannot distinguish them from here.
Either a second agent is running against this repository - which
`prompts/standing-loop.md` forbids precisely because "two writers on the same
files produce a diff nobody can review" - or something automated in the
environment is checking out branches. Either way the standing loop's one-session
assumption does not currently hold for this checkout, and a day's work can be
committed onto the wrong base without any error being raised. This is worth more
of the overseer's attention than the Maple access problem, because the Maple
