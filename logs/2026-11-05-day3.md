### Q-3 is partly answered by accident, and the answer is option 2

**This session was handed a `git worktree`**, at
`.claude/worktrees/timescape-experiment-day-3-65745f`, rather than the main
checkout. Nobody asked for it; the harness provided it. That is exactly
option 2 of Q-3 ("give each unattended session its own `git worktree`"), and
it is worth recording that it works:

- `git reflog` for this session shows only this session's own operations. No
  stray `checkout: moving from ... to verify-check` of the kind the second
  session recorded three times.
- A second process checking out branches in the main tree cannot move this
  session's `HEAD`, because this session's `HEAD` is a different file.

**Two caveats, because the mitigation is not complete.**

1. **The ref store is shared.** A worktree shares `.git/refs` with the main
   checkout, so another process can still create, move or delete *branches*,
   including `main` and this session's own branch. What it cannot do is move
   this session's checked-out `HEAD` or write to this session's files. That
   covers the failure actually observed in Q-3 (a commit landing on local
   `main` with the wrong tree) but not every failure of the shape.
2. **The git stash stack is shared too**, so `git stash` is unsafe across
   worktrees. No stash was used today; a temporary commit would be the route
   if one were needed.

So the recommendation on Q-3 stands as the second session wrote it, **3 plus
4**, with one amendment: option 2 is evidently cheap, it is already in place
for this session, and it should be made explicit in `prompts/standing-loop.md`
rather than left to the harness. Option 3's parent assertion is still worth
having, because it catches what the worktree does not. Written to
`OPEN-QUESTIONS.md` as an appended note under Q-3 rather than as a new
question, since it is evidence on an open question and not a new one.

## Cycle 3. WP-4: the mask behind the 1.5-point gap, and two wrong predictions of my own

**Package:** WP-4. The one piece of non-Maple in-scope work left.
**Evidence:** `verify/wp4_mask_resolution.py`, 16/16.
**Write-up:** `explain/004c-how-much-does-the-survey-edge-move-the-answer.md`.
**Finding:** `findings/WP-4-void-fraction.md` §11, appended.

### What was checked

`findings/WP-4-void-fraction.md` §3's closing sentence attributed the
1.48-point gap between this pipeline's VoidFinder void fraction (62.28%
Planck2018, 62.63% WMAP5) and arXiv:2202.01226 Table 6's (60.8%, 61.1%) to "the
1-degree mask resolution". **That was an assertion and neither of the two
previous sessions checked it.** It was load-bearing because §10.3 has
`f_v0 = 0.627` clearing the measured lower bound of 0.6228 by 0.0042, and the
unchecked gap is 3.5x that margin.

The method: the mask is a `(360, 180)` boolean sky grid at 1 degree and a
spatial cell is in-survey if its direction's pixel is set. Erode and dilate the
mask by one pixel and any finer mask of the same footprint, and any convention
differing from cell-centre lookup by under a pixel, lies between the two. The
sphere union does not depend on the mask, so it is rasterised once per
cosmology and reused across variants; that is what made eight variants
affordable inside one cycle. Three other candidates were varied in the same run
so the mask was not one hypothesis tested alone: the radial limit for WMAP5,
the denominator definition (rasterised cell count against analytic cone
volume), and the spatial grid.

### The result

**Confirmed.** The mask span is 3.07 points (Planck2018) and 3.06 (WMAP5)
against gaps of 1.48 and 1.53 — the mask covers the gap twice over — and the
published value lies **inside** the span in both cosmologies. The two pipelines
were never in conflict. The other three candidates come to 0.524 points
together: WMAP5's radial limit 0.490, the denominator 0.022, the grid 0.012.

Consequence for §10.3 and §10.4, which is the part that mattered. The measured
fraction is a lower bound, so the defensible value under a two-sided systematic
is the lowest, the dilated mask's 0.6045.

| bound | 0.550 | 0.557 | 0.627 |
|---|---|---|---|
| conservative, 0.6045 | excluded | excluded | +0.0225 |
| baseline, 0.6228 | excluded | excluded | +0.0042 |
| aggressive, 0.6352 | excluded | excluded | **excluded** |

**The committed conclusion holds and is better supported.** 0.550 and 0.557 are
excluded under every variant, 0.0545 and 0.0475 below even the conservative
bound. What sharpens is the third: 0.627's survival is now set by a one-pixel
footprint convention — clear by 0.0225 on the conservative reading, excluded by
0.0082 on the aggressive one. §10.3 called that margin too thin to trust and
was right; it is now quantified rather than merely suspected. K5 unaffected,
§8's second limb untouched.

### Negatives. Two predictions of mine, both wrong, both in the same run

**1. I predicted the mask would be refuted as the explanation, and was wrong by
a factor of six.** Written into the script's docstring before the first run:
`f_v` is a ratio, a mask change moves numerator and denominator together, so I
expected the full bracket to come to "well under 0.5 points". Measured 3.07.

The cancellation argument is right in form and wrong in magnitude, and it names
the term I then failed to evaluate: what survives cancellation is the
difference between the boundary layer's void fraction and the bulk's. Measured,
the layer dilation adds is **17.0% void against the survey's 62.3%**, because
the VoidFinder sphere union stops at the footprint edge and the mask does not.
A nearly void-free shell on the denominator and not the numerator moves the
ratio hard: 57% of an 8.6% volume change survives into it.

Per rule 6 the four checks that encoded the prediction were **inverted to
assert what is true**, the expectation was corrected in the docstring, and no
tolerance was widened. The first run's output is not committed, as nothing
under `verify/` keeps run output, but the failure is recorded here, in the
docstring, and in §11.3 of the finding.

**2. I predicted the denominator definition would be the larger lever** than
the mask, since it touches only the denominator and so has no cancellation to
rely on. It is the smaller by a factor of 140: the rasterised and analytic
volumes agree to 0.035%.

**3. A third, trivial:** I asserted that eroding and dilating each change the
footprint by over 5% of its set pixels. True figures 4.3% and 4.4%. The
threshold was corrected to 4%; it changes nothing downstream, but it was my
number and it failed.

**4. The 0.5 h⁻¹ Mpc grid run was not done.** 8x the cells is roughly 1.2 GB of
boolean grids and it was judged not worth the wall time once the 1→2 Mpc trend
came in at 0.012 points. Recorded as a deliberate omission rather than a
result, with its reason, so a later session can run it if the bound ever
matters at that level. It will not; the grid is converged.

### What was read, and how

VAST is public at `github.com/DESI-UR/VAST`. Cloned read-only into the session
scratch directory — **outside the repository**, treated as untrusted downloaded
content, nothing executed from it, nothing committed from it. Read at commit
`24e66e1` (repository head, pushed 2026-09-15) and **every claim re-checked at
`133cfcf` (2022-02-10)**, contemporaneous with arXiv:2202.01226's submission.
The relevant lines are identical at both, which is what makes the claim
`[SOURCED]` about the paper rather than about today's VAST.

### The result, which is a defect in this repository and not in the published one

`multizmask.py` line 15 sets `dec_offset = -90`. `generate_mask` scales and
truncates at line 166, `(mask_resolution*ang).astype(int)`, and writes at line
192, `mask[row[0], row[1] - mask_resolution*dec_offset]`.
`voidfinder_functions.py` line 249 reads
`survey_mask_ra_dec[int(n*ra), int(n*dec) - n*dec_offset]`. So the declination
index is `int(n·dec) + 90n`, truncating **toward zero**, in both the write and
the read. VAST is internally consistent.

**`verify/wp4_void_fraction.py` uses `((dec + 90) * res)` truncated** — offset
before truncation instead of after. Identical for `dec ≥ 0`; **one pixel apart
for every non-integer `dec < 0`**, because truncation toward zero rounds a
negative number up. 209 of the footprint's 9133 set pixels (2.3%) are southern
and SDSS DR7 reaches `dec ≈ -11`.

An array has to be read with the convention it was written with. The pickle was
written by `generate_mask`, so **VAST's expression is correct for this file and
this pipeline's is a defect**, not one of §11's variants. It is also a *shift*
rather than an erosion or dilation, so §11's erode-dilate pair does not bracket
it.

| | Planck2018 | WMAP5 |
|---|---|---|
| as committed | 62.280% | 62.628% |
| **corrected** | **61.570%** | **61.923%** |
| shift | −0.710 | −0.705 |
| residual vs Table 6, before | +1.480 | +1.528 |
| **residual vs Table 6, after** | **+0.770** | **+0.823** |

Same sign, nearly the same size, in both cosmologies. **Correcting the index
halves the disagreement with the published value.** §11's conclusion is
unaffected: +0.77 is still well inside the ±1.5-point pixelation systematic.
